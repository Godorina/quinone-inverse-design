## 1. 원칙

1. 기존 스키마, SHACL, CQ, `check.py`, `qextract`를 재사용한다. 새 phase마다 모듈은 하나만 두고, 새 CQ를 만들기보다 기존 CQ에 필터를 추가한다.
2. **기준 세트 SMILES 15개는 phase 7 전에 사람이 확인한다**(`smiles_proposals.csv`). 문헌 수치(`machine_extracted`)는 LLM 조회 문맥과 경향 확인에만 쓰고, 성공 판정에는 쓰지 않는다. 성공 판정은 우리 DFT 값으로만 한다.
3. 같은 조건, 같은 방법 서명, 같은 CO2 표준상태끼리만 비교한다. 호환되는지 알 수 없으면 제외한다.
4. 모든 지표에는 최소 표본 수가 있다. 표본 수가 모자라면 그 지표는 "측정 불가"로 보고하고, 통과로 간주하지 않는다.
5. 합격 수치는 실행 전에 이 문서에 고정한다. 바꾸면 이유를 DONE.md에 남긴다.
6. 문헌 KG와 설계 결과는 파일을 분리한다. 설계 결과는 문헌 Result로 승격되지 않는다.
7. 단순화한 곳에는 `# ponytail:` 주석을 달고, phase가 끝날 때 `ponytail-debt`로 목록을 만든다. 각 phase의 통과 여부는 독립 검토자가 정한다.

## 3. Phase 4b: 코퍼스와 추출 보강

> 개정 3(B안): 아래 2번(Morozova), 3번(방법 서명 재추출), 4번(기준 전극 환산), 7번(CO2 표준상태)은 phase 7~9에 쓰이지 않으므로 **미룬다**(스키마 필드는 이미 들어가 있다). B안에 필요한 것은 1번(38편 상태, 완료), 5번(SMILES, 사람 확인 필요), 6번(검수, 진행을 막지 않음)이다.

0. **환경.** RDKit은 `gpu4pyscf` conda 환경에 있는 것을 쓴다.
1. **엑셀 38편 상태 확정.** 각 논문에 `matched`, `added_on_topic`, `borderline`, `out_of_scope`, `unavailable` 중 정확히 하나를 붙인다. phase 1 라벨이 이미 있는 4편은 그 라벨을 재사용하고, 나머지 10편만 새로 판정하면서 근거를 1개 이상 인용한다. 엑셀 등급은 `qn:simReviewTier`(A/B)로 보관하고, B는 조회 문맥에만 쓴다.
2. **Morozova 2026.** 원문과 SI를 확보할 수 있으면 데이터 표를 원본 그대로 해시와 함께 `data/morozova2026/`에 보관하고, `qn:ScreeningDataset` 노드 하나로 연결한다. 확보할 수 없으면 `unavailable`로 둔다. 31,000개라는 숫자는 확인된 뒤에만 계획에 쓴다.
3. **방법 서명.** Measurement에 문자열 속성 `qn:functional`, `qn:basisSet`, `qn:solvationModel`, `qn:dispersion`, `qn:code`를 추가한다. 글에 없으면 `NotReported`로 둔다. `basis=Computation`일 때만 허용하는 SHACL 규칙을 하나 추가한다. 추출은 `qextract` 프롬프트에 필드를 더하는 방식이고, 인용 검사는 그대로 적용한다.
4. **기준 전극 환산.** 환산값은 **새 Condition**(환산된 기준 전극)을 가진 새 Measurement로 만든다. 원래 값과 같은 조건의 쌍으로 중복 집계되지 않게 하기 위해서다. 스키마에 `qn:derivedFrom`과 `qn:locator`를 추가한다. 환산 상수는 논문이 준 값만 쓴다.
5. **SMILES.** 쌍 후보 분자부터 채운다. LLM이 SMILES를 제안하면 RDKit으로 정규화하고 분자식을 대조한 뒤 사람이 확인한다. `qn:inchikey`와 `qn:smilesSource`를 추가한다.
6. **검수.** 이 계획에서 가장 중요한 사람 작업이다. 두 가지를 따로 한다.
   - (a) **수치 쌍 검수.** E1/2, ΔG/log K 쌍 후보 약 60개 이상을 원문과 대조한다. 대상 논문은 m007, m005, m015, Alherz, Schimanofsky, Massen-Hane(m077), Zhang 2026, Wang 2026 PAQ, Abdinejad이다. 그림에만 있는 값은 사람이 읽고 `qn:locator="Figure n"`으로 표시한다. m055는 손으로 입력한다. 담당자와 기한이 필요하다.
   - (b) **`human_review_40.csv` 감사.** 기계 추출의 오류율을 추정하는 용도다. 확정 오류가 나온 유형은 추출 규칙에서 먼저 실패 시험(RED)으로 재현한 뒤 고친다.
7. **CO2 표준상태.** 각 결합 값에 표준상태(1 atm 또는 1 M)와 ΔG↔log K 변환식을 기록한다. 이를 위해 Condition에 `qn:co2StandardState` 속성을 추가한다. 1 atm과 1 M의 차이는 이상기체로 환산하면 1.9 kcal/mol이지만, MeCN 실제 조건(Henry 법칙)에서는 CO2당 약 0.7 kcal/mol이다(외부 보고서, Zito & Yang 2024).

검사: 엑셀 DOI 집합에서 master DOI 집합을 뺀 결과가 비어 있고, 38행 모두 상태가 하나씩 있다. 계산값 중 서명 필드가 비어 있는 것은 0개다. SMILES는 모두 RDKit으로 파싱되고 분자식이 맞는다. 기존 시험이 모두 통과한다(현재 스키마 11, 추출기 74, 4b 2개).
게이트: B안(개정 3)에서는 분자 검수가 phase 7 진행을 막지 않는다. 검수 결과는 문헌 경향 확인과 LLM 문맥 신뢰도에만 쓴다(10절).

## 5. Phase 7: 기준 세트 DFT와 맞교환선

목적은 LLM 후보를 판정할 **기준선**을 우리 DFT로 만드는 것이다. 계산기 보정(xTB)은 하지 않는다. 사용자 결정에 따라 DFT만 쓴다.

1. **기준 세트**: `smiles_proposals.csv`에서 SMILES가 있는 분자 17개를 쓴다. InChIKey가 같은 2쌍을 합치면 15개다. 금속 착물, 고분자, 이미다졸륨 염은 뺀다.
2. **계산**: `dft/run_set.py` 하나를 새로 만든다(드라이버). `dft/dft.py`의 함수를 쓰며, 분자 목록을 받아 아래를 수행한다. 조건은 B3LYP-D3BJ/def2-SVP/SMD(MeCN)이고, 상태는 Q, Q•⁻, Q²⁻, Q²⁻·CO2, 그리고 CO2 한 번이다.
   - 부가물은 **최적화가 끝난 Q²⁻ 구조에 CO2를 붙여서** 시작한다. 벤치마크에서 RDKit 구조로 시작했더니 60단계, 610초가 걸렸다.
   - 결합 위치는 서로 다른 카보닐 O를 모두 계산하고 가장 낮은 값을 쓴다.
   - **O2와 O2•⁻도 같은 조건으로 한 번 계산한다.** O2 조건은 같은 방법 안에서 비교한다(E2 − E(O2/O2•⁻) ≥ 0.15 V). 페로센 환산은 하지 않는다. Spearman 비교는 순위 기반이라 기준 이동의 영향을 받지 않는다.
   - **CO2가 떨어져 나간 부가물**(O–C > 2.0 Å, `co2_detached`): 맞교환선 적합에서 빼고, 몇 개를 뺐는지 보고한다. 남은 점이 10개보다 적으면 선을 "측정 불가"로 보고한다. 후보에서 CO2가 떨어지면 실패로 센다.
   - 이미 끝난 분자는 결과 파일을 보고 건너뛴다. 중간에 멈춰도 다시 실행하면 이어서 계산한다.
   - 시간: 벤치마크에서 벤조퀴논(중원자 8개)이 13분 걸렸다. 안트라퀴논 크기(중원자 16개)는 2~3배이고, 결합 위치가 다르면 부가물을 하나 더 계산해야 한다. 15개 ÷ GPU 2장이면 **약 4~8시간**이다. 첫 3개를 계산한 뒤 실측으로 다시 추정한다.
3. **맞교환선**: `ΔE_bind = a·E2 + b`를 기준 세트로 적합하고, 잔차 표준편차 σ를 구한다.
   - 이번 회차는 전자 에너지만 쓴다(`# ponytail: 진동/자유에너지 보정 없음. 후보와 기준을 같은 방식으로 비교하므로 상대 비교는 유지된다. 절대값을 문헌과 비교할 때 추가`).
4. **문헌과 경향 확인 (보고만 한다)**: 검수된 실험값이 있는 분자에 대해 기울기 부호와 Spearman을 보고한다. 표본이 10개 미만이면 "측정 불가"로 적는다.

검사:
- `make test`의 DFT 시험(구조, 부가물 기하)
- 벤치마크 재현: `make bench`
- 부가물 시작 구조가 최적화된 Q²⁻ 좌표를 쓰는지 확인하는 시험 1개

## 6. 이번 회차 방식: B안 (개정 3)

사용자의 원래 목표는 **온톨로지를 만들고, LLM이 그 근거로 신소재를 제안하는 것**이다(ontology-mlip 방식). 개정 2의 닫힌 루프(제안 수천 개를 DFT로 평가)는 DFT만 쓰면 20~30일이 걸려서 이번 회차에서는 하지 않는다.

```
논문 → 온톨로지(KG) → LLM이 KG 근거를 인용해 후보 SMILES 제안 → 근거·화학·중복·신규성 검사
    → 상위 10개만 DFT로 확인 (같은 예산으로 무작위 편집 10개도 확인) → 결과를 KG에 기록
```

- **역설계 여부**: 목표(맞교환선보다 유리하고 O2에 강함)에서 출발해 LLM이 구조를 제안하므로, 목표 지향 생성이다. 평가 결과를 생성기에 되돌리는 반복 최적화(좁은 의미의 역설계)는 아니다. 결과 보고에서 이 점을 그대로 밝힌다.
- **나중에 확장할 때**: 개정 2의 닫힌 루프(`.omc/plans/PLAN.rev2.md` 6~8절)를 쓴다. `onto/phase_8_design/loop.py`(검증 완료)를 그대로 재사용한다.

## 7. Phase 8: KG 근거 LLM 후보 생성

1. **조회**: SPARQL(phase 5 KG)로 기준 세트 분자, 검수된 E2와 결합값, 치환기 효과, 산소 관찰을 표로 만든다. 짧은 ID와 원래 IRI의 대응을 남긴다.
2. **생성**: LLM을 4번 호출하고, 호출마다 10개씩 총 40개를 제안받는다. 피드백은 없다. **`loop.run`은 쓰지 않는다.** 이 함수는 통과한 후보 전부를 평가자로 보내기 때문이다. 대신 `phase_8_design/generate.py`(짧은 스크립트)가 `loop.py`의 `t0`, `in_domain`, `edit`만 가져다 쓴다.
   - 출력 필드: `parent_id, edits[], smiles, cited_ids[], hypothesis`
   - 편집 연산은 `loop.py`의 것을 쓴다: 치환기 추가, 교체, 제거, 위치 이동.
   - 근거가 부족하면 `insufficient_evidence`로 끝낸다.
3. **검사** (`loop.py`의 함수를 재사용):
   - T0: 파싱, 원자가, 퀴논 패턴, 중원자 40개 이하
   - 적용 영역: 코어 SMARTS, 치환기 범위
   - 인용 ID가 KG에 실제로 있는지
   - 전체 KG와 Morozova 데이터(있으면)를 대상으로 InChIKey 중복 검사
4. **선정**: LLM이 출력한 순서대로 검사를 통과한 후보 중 처음 10개를 고른다. 같은 코어와 같은 치환기 집합은 하나만 남긴다. 선정 순서와 탈락 이유는 원장(JSONL)에 남긴다.
5. **기준선 B0**: LLM 후보와 같은 비율로 부모 분자를 고르고, 무작위 편집으로 후보를 만든다. **같은 검사**(T0, 적용 영역, InChIKey 중복)를 통과한 처음 10개를 쓴다. DFT 계산도 똑같이 한다.
6. **차별성 심사**: 생성자와 다른 검토자가 한다. 표현은 "등록 범위 안에서 중복 없음"까지만 쓴다.
7. **LLM**: Claude CLI(`claude -p`, ontology-mlip과 같은 방식)를 쓴다. GPU를 쓰지 않으므로 DFT와 겹치지 않는다. 호출은 4번이다.

## 8. Phase 9: DFT 확인과 보고

- **계산**: LLM 후보 10개와 B0 10개를 5절과 같은 조건으로 계산한다. 20개 × 약 15~30분 ÷ GPU 2장 ≈ **5~10시간**(첫 기준 세트 실측으로 다시 추정).
- **판정**:
  - `f = (a·E2 + b − ΔE_bind) / σ`. 맞교환선보다 유리한 쪽이 양수다.
  - **성공**: f ≥ 2이고, 같은 방법으로 계산한 O2/O2•⁻보다 E2가 0.15 V 이상 양이며, CO2가 떨어져 나가지 않는다.
- **보고**:

| 항목 | 내용 |
|---|---|
| LLM 후보 | 성공 개수, f 분포, 최고 f |
| B0 대비 | f 중앙값 차이와 Mann-Whitney 단측 p(n = 10 대 10). 검정력이 낮으므로 효과 크기 위주로 보고한다 |
| 품질 | T0 통과율, 적용 영역 안 비율, 인용 유효율, 중복률 |
| 실패 분석 | 실패 유형별 개수와 대표 사례 |

- **기록**: 원장은 JSONL로 남긴다. 최종 후보 20개만 `design.ttl`에 `basis=Computation`으로 저장한다. 결과를 KG에 기록하는 것이 이 프로젝트 목표의 일부이기 때문이다. 문헌 KG와는 파일을 나누고, 다시 읽어서 JOIN이 되는지 확인한다.

## 9. 위험

| 위험 | 대응 |
|---|---|
| 기준 세트가 작음(15개) | σ를 함께 보고하고, 결론은 "이 기준 세트 대비"로 한정 |
| 전자 에너지만 씀 | 같은 방식으로 상대 비교만 하고, 절대값 비교는 범위 밖으로 명시 |
| def2-SVP에 diffuse 함수가 없음(이음이온) | 상위 후보는 필요하면 def2-TZVPD로 단일점 재계산 |
| 연속체 용매 모델의 E2 오차: 0.3~0.4 V (Alherz 2022 −0.37 V, Elhajj 2024 320~410 mV) | 절대 전위는 주장하지 않는다. 같은 방법 안의 상대 비교(f, O2 조건)만 한다. 실험값과 절대 비교하려면 Fc와 자유에너지, 그리고 선형 보정 허용 여부가 필요하다(10절) |
| LLM의 인용 날조, 신규성 과장 | 기계 인용 검사, 전체 KG 중복 검사, 표현 제한 |
| 부가물 최적화가 느림 | Q²⁻ 최적화 구조에서 시작 |
| GPU 충돌 | llama-server는 꺼 둔다(재시작 명령은 `.omc/llama-server.restart.sh`) |
| 합성 가능성, 용해도 | 범위 밖. SA 점수는 참고값 |
